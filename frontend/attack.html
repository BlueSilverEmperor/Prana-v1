Attack vs Defense

A Markov chain Monte Carlo search generates transactions and throws them at rules R1–R12. Red chains mutate attacks, which must be blocked. Green chains mutate safe payments, which must pass. No dataset, no sample list: every transaction is generated in the run and every verdict comes from the rules.

    Immune system

    One vault is attacked, every vault is protected

    When the rules block an attack, the address the attack relied on (a fake implementation, an unlimited spender, a backdoor module, a lookalike recipient) is reported. Once 2 different vaults report the same address, it joins the threat registry and rule R12 blocks it for everyone. Token contracts, the vault itself and its declared contacts are never vaccinated.

    1. Press the button to watch an attacker hit three vaults.

    Each run uses a new random attacker address and new vaults, sent to the live engine at /v1/simulate; the registry is read from /v1/vaccines.

    How the search works

    1. Start Red chains start from an attack (logic swap, unlimited approval, lookalike payment, unknown recipient). Green chains start from a safe payment to the declared wallet within the declared cap.
    2. Mutate Each step changes one thing: the method (9 kinds), the recipient, the amount, CALL or DELEGATECALL, MultiSend nesting, padding, splitting the drain into several calls, or hiding it behind a legitimate declared payment.
    3. Judge twice The rules give a verdict. Separately, the transaction's real effect decides whether it is an attack (moves value or control beyond what was declared) or safe.
    4. Keep the near-misses Metropolis–Hastings keeps moves that get closer to fooling the rules: harmful but allowed for red, safe but blocked for green.
